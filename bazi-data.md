# Four-pillars data

`/bazi/` turns a birth date and time into the year, month, day and hour pillars. It
computes a calendar chart and nothing else — no interpretation, no scoring, no
prediction. That scope is enforced by what the code is allowed to return: four
stem-branch pairs, an element tally and the governing solar term.

## Conventions (fixed, and stated on the page)

- **Time zone:** China Standard Time (UTC+8), which is how `sxtwl` reports moments.
- **Year pillar:** changes at 立春, not 1 January and not Lunar New Year.
- **Month pillar:** changes at the twelve 节 (小寒, 立春, 惊蛰, … 大雪).
- **Day pillar:** changes at 23:00 (晚子时), so 23:00 or later uses the next day.
- **Unknown birth time:** the hour pillar is omitted, never guessed.

The 23:00 rule is a convention, not a consensus — some schools switch at midnight.
The page says so rather than presenting one choice as fact.

## Provenance

`bazi-data.json` and `bazi-data.js` were generated by `tools/make_bazi_data.py`
from **sxtwl** (寿星天文历) at development time. Every 节 from 1900 to 2100 is
stored as `MMDDHHmm`, rounded **up** to the next whole minute so a term is never
treated as passed before it has.

- https://pypi.org/project/sxtwl/
- The libraries are used only during development; nothing is fetched at runtime.

Regression anchors: epoch day 1900-01-01 = 甲戌 (cycle index 10); 2026 立春 =
2026-02-04 04:02 (Beijing); 2026 is 丙午.

## Verification

```bash
python tools/make_bazi_data.py   # regenerate data + vectors
node tools/check_bazi.js
```

`tools/check_bazi.js` asserts:

1. `bazi-data.js` and `bazi-data.json` are byte-identical in content.
2. 201 years × 12 terms, every term a valid `MMDDHHmm` string.
3. 184 dated charts match values generated independently from `sxtwl` — all four
   pillars, including the 晚子时 cases.
4. 144 boundary cases: one minute either side of every 节 in six sample years. The
   month branch must flip at the moment, and 立春 must flip the year pillar.
5. An empty birth time yields three pillars and no hour pillar.
6. A year outside 1900–2100 throws instead of returning a plausible-looking chart.

## Independent cross-check

The vectors above come from `sxtwl`. To avoid a single-implementation blind spot,
the browser code was also compared directly against **lunar-javascript 1.7.7**
(MIT, `https://cdn.jsdelivr.net/npm/lunar-javascript@1.7.7/lunar.js`) — a separate
project with its own ephemeris — on 1528 datetimes (every vector plus a 1200-date
random sample). Result: **0 mismatches** under lunar-javascript's `sect 1`.

That sect distinction is exactly the convention the page warns about: `sect 1`
shifts the day pillar at 23:00 (晚子时), which is what this site uses; `sect 2`
keeps the day pillar on the birth date. Same input, one-hour window, two answers —
which is why the page states the rule instead of hiding it.

Known limitation: chart output is minute-resolution. A birth within a few seconds
of a solar term can land on either side. Traditional readings also weigh hidden
stems (藏干) and seasonal strength, which this calculator does not model — and does
not pretend to.
